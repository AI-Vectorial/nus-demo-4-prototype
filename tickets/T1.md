## What we are building

The first working version of Aldermere's policy assistant: staff can ask a policy
question, get an answer grounded in the bank's policy documents, and see the sources
used. Follow-up questions in context come in the next increment.

## Why it matters

Without it, staff still have to manually search through multiple policy documents to
find answers, making policy questions slower and harder to verify. More importantly,
there is a risk of giving a confident answer that the policies do not actually support.

## Acceptance criteria

*Every line is pass or fail. Numbered so the child tickets, the review and the release
can refer to them.*

### F1 — ingest

- [x] **1.** From an empty collection, `python -m app.ingest` exits successfully and all five corpus files have at least one passage, with Travel v3.0 stored as `status: superseded`   *(REQ-I1, REQ-I7)*
- [x] **2.** Every passage has non-empty `text`, `document_id`, `document_title`, `section`, `version`, `status` and `effective`   *(REQ-I3)*
- [x] **3.** A second `python -m app.ingest` leaves the passage count and the set of passage ids identical   *(REQ-I4)*
- [x] **4.** `--force` recreates the collection and re-embeds everything; count and ids afterwards match the original run   *(REQ-I5)*
- [x] **5.** No passage crosses a section boundary, and every passage ends at the end of a sentence   *(REQ-I2)*
- [x] **6.** Indexing makes at most ⌈passages ÷ `EMBEDDING_BATCH_SIZE`⌉ embedding calls, verified with the fake model   *(REQ-I6)*

### F2 / F3 — retrieve and refuse

- [x] **7.** Each of the 10 answerable questions in `EVALUATION.md` returns grounded passages (not a refusal) with the expected document **and** section in the top 3 — for Q1/Q2 that is **Travel v3.1** §4.2, not v3.0   *(REQ-R1, REQ-R5)*
- [x] **8.** Every passage retrieval returns scores at or above `MIN_SCORE`   *(REQ-R2)*
- [x] **9.** Each of the 3 out-of-scope questions returns an explicit insufficiency — a distinct type/outcome, not an empty list   *(REQ-R3, REQ-R6)*
- [x] **10.** When retrieval is insufficient, the model is called **zero** times — asserted by a test counting fake-model calls   *(REQ-R3, NFR-2)*
- [ ] **11.** A refused `/ask` returns in **under 1.5 s** on the local stack   *(NFR-2)*
- [x] **12.** Setting `MIN_SCORE` above any possible score (e.g. `1.01`) makes all 13 questions refuse with no code change, and a grep of `app/` finds no numeric threshold literal   *(REQ-R4)*

### F4 — generate

- [x] **13.** Every citation in an `answered` response matches a passage retrieval returned for that question — same document, section, version   *(REQ-G1, REQ-G3)*
- [x] **14.** The prompt sent to the model contains only the question, the retrieved passage texts, and an instruction to answer from them alone — checked by capturing what the fake model received   *(REQ-G1, REQ-G2)*
- [x] **15.** The prompt is loaded from a file under `backend/app/generate/` that declares its version; no prompt text appears as a string literal in Python   *(REQ-G4)*
- [ ] **16.** Every `answered` response has `latency_ms`; the stored assistant message records `model`, `prompt_version` and `latency_ms`, and `prompt_version` equals the prompt file's version   *(REQ-G5)*
- [x] **17.** With `GENERATION_ENABLED=false`, an answerable question returns `outcome: "degraded"`, `answer: null`, non-empty `citations`, and zero model calls   *(REQ-G6, NFR-3)*
- [x] **18.** When the model raises a timeout or connection error (simulated with the fake model), the same question returns the degraded shape of 17, not an error   *(REQ-G6, NFR-3)*
- [x] **19.** With `GENERATION_ENABLED=false`, an out-of-scope question returns `outcome: "refused"`, not `degraded`, with zero model calls   *(REQ-R3, REQ-G6)*
- [ ] **20.** *(manual, stage 06)* Asking Q7 and Q4 on the live app: every figure in the answer appears in the cited passages, and the answer names no regulation, regulator or source outside the corpus   *(REQ-G1, REQ-G2)*

### F5 — ask and show it

- [ ] **21.** Every `/ask` response carries an explicit `outcome` plus `conversation_id`, `message_id` and `latency_ms`, and matches PRD §5 per outcome — `answered`: text + non-empty citations · `refused`: reason text + `citations: []` · `degraded`: `answer: null` + non-empty citations   *(REQ-A1, REQ-A2)*
- [ ] **22.** `/healthz` reports database, vector store and model reachability separately; with Postgres or Qdrant stopped it still responds and names the one that is down   *(REQ-A5, NFR-5)*
- [ ] **23.** After a first question (`conversation_id: null`) the database holds 1 new `conversations` row, 2 `messages` rows (user question; assistant reply with its `outcome`), and one `message_citations` row per response citation with matching document, section, version, status and score   *(REQ-C1, REQ-C2)*
- [ ] **24.** A second `/ask` with that `conversation_id` stores its 2 messages under the same conversation and creates no new one   *(REQ-C1, REQ-C2)*
- [ ] **25.** Opening `/` shows a centred input with a send control and no conversation   *(REQ-U1)*
- [ ] **26.** After sending, the question appears at once with a pending indicator until the response arrives   *(REQ-U2, REQ-U7)*
- [ ] **27.** An answered question shows the answer and its citations with no click needed; each citation shows document title, section, version and status   *(REQ-U2, REQ-U3)*
- [ ] **28.** A superseded citation is visibly marked — a "Superseded" label in the PRD warning colours. *Revisit after D4*   *(REQ-U4)*
- [ ] **29.** A refusal (Q11), an error (API stopped) and a degraded response (`GENERATION_ENABLED=false`) each render as a distinct, labelled component; degraded is labelled as retrieved passages, not an answer   *(REQ-U5, REQ-U6)*
- [ ] **30.** Every route has a top bar with exactly **Reset · History · Corpus**, and no sidebar, hamburger or settings; Reset clears the screen and the next question starts a new conversation   *(REQ-U9)*
- [ ] **31.** At 375 px width there is no horizontal scroll, and the input, answer and citations are usable   *(REQ-U10)*
- [ ] **32.** No theme toggle and no dark-mode styling; colours match PRD §4   *(REQ-U11)*
- [ ] **33.** **History** and **Corpus** open `/history` and `/corpus` as "coming soon" pages with the top bar present — never a 404 or a blank page   *(REQ-U9)*

## Out of scope

- **F6 follow-up in context** — REQ-C3 .. REQ-C9, decisions D8 and D9. A second question is stored in the same conversation (24) but answered without earlier turns
- **F7 corpus browser** — REQ-B1 .. REQ-B6, REQ-A4, REQ-U12, **REQ-U15** (a citation opening its section). `/corpus` is a "coming soon" page for now
- **F8 history** — REQ-A3, REQ-A6, REQ-U13, REQ-U14. `/history` is a "coming soon" page for now
- **F9 – F12** — only after F5 is deployed
- **Policy editing** — ingestion reads `backend/corpus/`; nothing modifies a policy document
- **Automatic re-indexing on document change** — ingestion stays an explicit command
- **General knowledge or web search** — answers come from the corpus only
- **Streaming responses**
- **A settings UI** — configuration stays in environment variables
- **Authentication, users, sessions**

Superseded documents are **not** removed from ingestion — REQ-I7 indexes them with
`status: superseded`. How they are presented is D4.
